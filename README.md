# Company Radar

A full-stack company research tool for software engineers evaluating potential employers. Enter a company name and your profile — get a structured intelligence report with green flags, red flags, and a verdict.

## Architecture

| Layer | Technology |
|-------|-----------|
| Frontend | Next.js 14 (App Router, TypeScript) — Vercel |
| Backend | Python FastAPI + LangGraph — Render Web Service |
| LLM | Groq API (`llama-3.3-70b-versatile`) |
| Embeddings | fastembed (`BAAI/bge-small-en-v1.5`, runs inside the backend process) |
| Web Search | SearXNG — Render Docker Web Service (separate) |
| Web Scraping | Playwright (Chromium) |
| Vector Store | ChromaDB (embedded, persists to `./chroma_data`) |

## How It Works

1. You enter a **company name** and your **profile** (experience, target role, priorities, reason for leaving)
2. The **Planner** generates 11 targeted search queries (site-specific: Glassdoor, AmbitionBox, Reddit, TeamBlind, Levels.fyi, Naukri, etc.)
3. The **Search & Embed** node runs queries via SearXNG, scrapes pages with Playwright, chunks and embeds text with fastembed, and stores results in ChromaDB
4. The **Synthesizer** retrieves the top 20 most relevant chunks via cosine similarity and generates a structured report using Groq
5. If research gaps are detected, the loop runs up to 3 iterations with gap-filling queries
6. The final report streams to the browser with:
   - Company vitals (size, funding, ratings, salaries, remote policy)
   - Green flags with inline citations
   - Red flags with inline citations
   - Verdict: **PURSUE / CAUTION / AVOID**
   - Non-obvious insights

## Local Development

### Prerequisites

- Docker (for running SearXNG locally)
- Python 3.11+
- Node.js 18+
- Groq API key — https://console.groq.com

### 1. Start SearXNG

```bash
docker compose up -d
```

SearXNG will be available at `http://localhost:8080`. The included `settings.yml` enables JSON output format automatically.

### 2. Configure environment

```bash
cd backend
cp .env.example .env   # add your GROQ_API_KEY

cd ../frontend
cp .env.example .env   # defaults work for local dev
```

### 3. Install Python dependencies

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
```

The fastembed model (`BAAI/bge-small-en-v1.5`, ~45 MB) downloads automatically on first run.

### 4. Start the backend

```bash
cd backend
source .venv/bin/activate
uvicorn main:server --port 8000 --reload
```

### 5. Install and start the frontend

```bash
cd frontend
npm install
npm run dev
```

### 6. Open http://localhost:3000

## Deployment

Production architecture:

```
GitHub (main branch)
  │
  ├── GitHub Actions (CI/CD)
  │     ├── check-backend  (syntax check)
  │     ├── check-frontend (tsc --noEmit)
  │     └── deploy (triggers Render deploy hooks if checks pass)
  │
  ├── Render ── company-radar-searxng  (Docker web service)
  │         └── company-radar-backend  (Python web service)
  │
  └── Vercel ── company-radar-frontend (auto-deploys on push)
```

### 1. Deploy SearXNG to Render

SearXNG is defined in `render.yaml` as a Docker Web Service — Render builds and runs the container, you manage nothing. `searxng/Dockerfile` wraps the official image with your settings.

In Render Dashboard, after the service is created, set these env vars:
- `SEARXNG_SECRET_KEY` — auto-generated by `render.yaml`
- `SEARXNG_BASE_URL` — set to `https://company-radar-searxng.onrender.com`

### 2. Deploy backend to Render

Defined in `render.yaml` as a Python web service. Render runs the build command which installs Playwright's Chromium automatically.

Set these env vars in the Render Dashboard:
- `GROQ_API_KEY` — your Groq API key
- `SEARXNG_URL` — `https://company-radar-searxng.onrender.com/search`
- `ALLOWED_ORIGINS` — `https://your-app.vercel.app`

### 3. Deploy frontend to Vercel

Connect the GitHub repo to Vercel (root directory: `frontend`). Set:
- `BACKEND_URL` — `https://company-radar-backend.onrender.com`

Vercel auto-deploys on every push to `main`.

### 4. Set up CI/CD (GitHub Actions)

The workflow (`.github/workflows/deploy.yml`) runs checks on every push and PR, then deploys to Render on merges to `main`.

To enable the deploy step, add these secrets in GitHub → Settings → Secrets → Actions:

| Secret | Where to get it |
|--------|----------------|
| `RENDER_BACKEND_DEPLOY_HOOK` | Render Dashboard → backend service → Settings → Deploy Hook |
| `RENDER_SEARXNG_DEPLOY_HOOK` | Render Dashboard → SearXNG service → Settings → Deploy Hook |

Once set, every push to `main` runs checks → deploys both Render services if they pass. Vercel deploys independently in parallel.

| Variable | Required | Description |

## Notes

- Each research session creates a fresh ChromaDB collection; old collections are cleaned up after 7 days
- SearXNG must be reachable from the backend — if unavailable, search falls back to DuckDuckGo automatically
- The full process takes 2–5 minutes depending on network speed and number of iterations
- fastembed runs inside the backend process — no separate embedding service needed
- Local development still uses Docker for SearXNG via `docker compose up -d`
